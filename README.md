# Читальня — «Управляя поведением»

Закрытое веб‑приложение (PWA), где читатели работают с черновиком книги
и помогают сделать её лучше. Фронтенд — статические HTML‑файлы,
бэкенд — Supabase (база данных + edge‑функции).

## Структура

| Файл | Назначение |
|------|------------|
| `index.html` | основное приложение (читалка, комментарии, админ‑панель) |
| `solve-home.html`, `explore.html`, `quests.html`, … | отдельные экраны |
| `config.js` | ключи Supabase (`SUPABASE_URL`, `SUPABASE_ANON_KEY`) |
| `sw.js` | service worker (офлайн‑режим) |
| `manifest.json` | манифест PWA |
| `icon-*`, `apple-touch-icon.png` | иконки |

## Бэкенд (Supabase)

- Проект: **Bookz** (`wsnqmjzmtjpezkzlzhra`, регион eu-west-1).
- Ключи хранятся в `config.js`. `anon`‑ключ публичный — доступ к данным
  закрыт правилами RLS в базе. Ключ `service_role` в репозиторий класть **нельзя**.
- Миграции и edge‑функции применяются на стороне Supabase.

## Как выкладывать файлы в GitHub

Раньше файлы заливались вручную через «Add files via upload».
Теперь это делается через git — без ручной загрузки:

```bash
# 1. внести изменения в файлы (отредактировать или добавить новые)
# 2. посмотреть, что изменилось
git status

# 3. добавить файлы в коммит
git add index.html config.js          # конкретные файлы
# или: git add -A                      # все изменения

# 4. зафиксировать с понятным описанием
git commit -m "Обновить читалку: …"

# 5. отправить в GitHub
git push -u origin <имя-ветки>
```

После пуша изменения видны на https://github.com/temkaavdeev-ctrl/book-reader
в соответствующей ветке. Чтобы они попали в основную версию сайта,
ветку нужно слить в `main` (через Pull Request на GitHub).
